# Participant and physical-accessibility protocol

Prepared tasks, not performed research. No participant, physical-device,
NVDA or VoiceOver pass is recorded by desktop browser automation.

Use consented test identities and a separate evaluation dataset. Do not collect
passwords, tokens, real email addresses or unnecessary personal information in
observation notes. A facilitator records completion, errors, assistance and the
participant's own description of confusing feedback.

| Role | Task | Observe |
| --- | --- | --- |
| Student | Discover an event, understand eligibility, register, find the result in My Events | Seat counts, confirmation, retry and next action understood |
| Club member | Combine My Clubs with an organization/event-name search, then join a full event | Search scope, waitlist position and no-estimate message understood |
| Organization administrator/moderator | Use desktop drafts/preview and an accreditation-limited action; inspect attendee mobile experience | Disabled actions explain their reason; no mobile management controls |
| Faculty member | Identify eligibility, complete a profile, register and enter confirmed chat | Faculty-inclusive copy and privacy boundaries understood |

Repeat critical attendee tasks with Filipino, extra-large text, dark/high
contrast and reduced motion. Test all six existing viewport sizes in automation.
On physical Android and iOS, separately record device, OS/browser version,
keyboard behavior, scrolling, safe areas and reachable confirmation actions.

With NVDA and VoiceOver separately verify page headings, labels, dialog names,
focus containment/return, error announcements, retry status and waitlist results.
Keyboard-only testing includes visible focus, logical tab order and no traps.

Inject a slow/cold API, 429 with Retry-After, connection loss and validation
failure. A retry must retain its original operation key and entered values.
Ask participants what they expect before they activate retry or registration.

| External gate | Status | Required evidence |
| --- | --- | --- |
| Actual participants across the four roles | Pending | Consented observations and defect follow-up |
| Physical Android | Pending | Device/version and completed tasks |
| Physical iOS | Pending | Device/version and completed tasks |
| NVDA | Pending | Actual reader/browser results |
| VoiceOver | Pending | Actual reader/browser results |
| Positive live PLM verification | Deferred by user | Resume only when explicitly requested |
